# GEOFlow B2B 高质量出海博客与 GEO 生产管线 (GEOFlow B2B SEO Blog Pipeline)

本技能提炼自工业品出海独立站营销与 GEOFlow 内容引擎的实战升级成果，深度融合 **QuickCreator 创始人 Tony Yan 提出的 AI SEO 5 步高质量生产链路**（搜索意图挖掘、受众调控、大纲人机协同、On-Page SEO 赋能、CTA 转化闭环）、**企业级原子物理事实治理体系**（11 项核心物理基线、F001–F031 事实台账、不可变 SHA-256 审核签名与 Astro 静态发布门禁）与 **guizang-social-card-skill 瑞士国际主义工商业视觉卡片引擎**。

---

## 一、 核心定性与底层原则

### 1. 为什么“批量 AI 机翻多语言博客”无法获得外贸询盘？
* **Google 算法降权（Helpful Content Update）**：针对脱离一手事实、模板化洗稿、无海外真实搜索意图支撑的“规模化内容滥用（Scaled Content Abuse）”，实施域名级沙盒压制；
* **B2B 采购决策极重**：工业装备（如便携式路灯立杆机）涉及高客单价与现场作业安全，买家需要具体承载力矩、安装工况、对比测算与图纸审核，泛泛而谈的 AI 水文无法建立商业信任；
* **视觉信任断层与转化路径缺失**：缺乏一手产品工程实景与清晰图表支撑，缺乏上下文内链引导、缺少可操作的决策工具（ROI 计算器、法兰孔距复核、规格书下载），读者读完即走，无法沉淀为有效询盘（Inquiries）。

### 2. 核心三层破局法则
1. **意图与大纲先行（Outline-First & Intent-Driven）**：不打无准备之仗。以海外买家真实搜索词（SERP/PAA）逆向指导大纲，将事实台账编号（F001–F031）显式挂载到各章节；
2. **正文即转化漏斗与工商业视觉阵列（Content as Conversion Funnel & Visual System）**：开篇输出高密度 **Key Takeaways** 与 16:9 全景头图，正文深度集成 `geoflow-article-illustration` 的**瑞士工商业信息图卡（16:9/3:4/1:1）**、**三级梯度 CTA** 与**站内高权重内链**，文末输出符合 **Schema.org** 的 FAQ；
3. **安全多语言矩阵演进（English First $\rightarrow$ Fact Freeze $\rightarrow$ 7-Language Matrix $\rightarrow$ GEOFlow Admin Review）**：依据网站语言分布（`en`, `es`, `fr`, `pt`, `vi`, `th`, `id`），严禁无基准批量机翻。单语跑通英文母版，在强制锁死物理数值与 URL 路径的前提下，一键同步生成 7 语种矩阵文章与专属多语种配图，并自动同步入库 GEOFlow 数据库后台（`status='draft', review_status='pending'`），由管理员在 `http://127.0.0.1:18082/geo_admin/articles` 统一集中人工审核。

## 三、 执行规范与各阶段 SOP

### Step 1: 海外 SERP 意图雷达与 LSI 语义拓词
* **目标**：挖掘海外目标市场（US/AU/SA）真实买家搜索痛点，消除“闭门造车式自嗨”。
* **执行步骤**：
  1. 调用 `OverseasSerpIntentService`（或参考 [01_serp_intent_and_lsi_radar.md](./references/01_serp_intent_and_lsi_radar.md)）；
  2. 提取海外 Top 10 竞品 H2 框架；
  3. 沉淀 **People Also Ask (PAA)** 真实采购提问（如：*How many workers needed to erect 10m pole?* / *What is the max lifting weight?*）；
  4. 锁定共现 LSI 关键词（如 `crane rental rates`, `flange bolt circle`, `narrow access erection`）；
  5. 设定目标受众阅读难度（Grade 8–10 工程采购语言风格，客观克制）。

### Step 2: 渐进式大纲人机协同与原子事实挂载
* **目标**：拆分“单步盲写”为两阶段，确保每个章节都有明确工程事实支撑与商业使命。
* **执行步骤**：
  1. 依据 [02_outline_first_fact_governance.md](./references/02_outline_first_fact_governance.md) 生成 4–6 个 H2 大纲树；
  2. 显式挂载企业原子物理事实编号：
     * `F002`: 额定垂直载荷严格标称 300kg（垂直试验台核定）；
     * `F003`: 最大适配杆高 12m；
     * `F004`: 工作动力 24V DC 电池；
     * `F008`: 分体包装重量 85kg（两名作业人员轻松搬运）；
     * `F015`: 通用底板适配地脚螺栓分布圆直径（P.C.D.）180mm 至 260mm；
     * `F016`: 标配容纳 M16 至 M24 锚栓；
     * `F020`: 出厂 100% 垂直载荷与液压保压质检；
  3. 为小节标注拟埋设的转化漏斗阶段（`none` / `top` / `mid` / `bottom`）；
  4. 支持大纲导出，经人工或评审 Agent 确认后方可触发正文扩写。

### Step 3: 结构化扩写与合规防线门禁
* **目标**：生成具备极高信息密度且零虚假宣传的专业长文。
* **执行步骤**：
  1. 使用 [article_prompt_template_en.md](./templates/article_prompt_template_en.md) 作为生成母版；
  2. **开篇要点卡片**：在 H1 导语后必须输出 `> ### 📌 Key Takeaways for Project Engineers` 包含 3–4 条硬核结论；
  3. **合规红线门禁**：
     * 严禁宣称任何虚假认证（严禁出现 "CE certified"、"ISO certified"）；
     * 严禁宣称“保证回本（guaranteed payback）”或“单人作业（one-person operation）”；
     * 严禁输出原始货币符号（`$`、`€`、`£`、`¥`）；
     * 严禁虚构联系邮箱或电话，统一引导至站内合规表单。

### Step 4: On-Page SEO 站内内链网络织网
* **目标**：将博客页面融入整站 PageRank 拓扑，杜绝孤岛页面（Orphan Pages）。
* **执行步骤**：
  1. 依据 [03_internal_link_weaving_topology.md](./references/03_internal_link_weaving_topology.md) 维护主站核心路由映射表：
     * `/tools/roi-calculator/` $\leftarrow$ 锚文本：`crane rental cost savings`, `calculate lifting equipment roi`
     * `/guides/pole-jack-compatibility/` $\leftarrow$ 锚文本：`flange bolt circle compatibility`, `base plate engineering review`
     * `/compare/pole-jack-vs-crane/` $\leftarrow$ 锚文本：`crane alternative for tight spaces`, `boom truck comparison`
     * `/products/light-pole-jack/` $\leftarrow$ 锚文本：`12m portable light pole lifter`, `portable hydraulic pole lifter`
     * `/quote/` $\leftarrow$ 锚文本：`request factory quotation`, `factory engineering drawing audit`
  2. 运行 `InternalLinkInjector` 智能扫描，段落自然穿插；
  3. 单篇每条路由链接 $\le 1$ 次，全文总链接 $\le 4$ 次，严禁在标题（H1/H2/H3）内植入链接。

### Step 5: 外部行业标准引证与三级 CTA 转化闭环
* **目标**：拉升 Google EEAT（专业度与可信度），并将读者平滑引导至商业询盘。
* **执行步骤**：
  1. 依据 [04_authoritative_standards_citations.md](./references/04_authoritative_standards_citations.md) 引入外部标准白名单：
     * 起重与临电安全：`OSHA 1926 Subpart CC (29 CFR 1926.1408)`；
     * 道路照明设计：`ANSI/IES RP-8-18`；
     * 地脚螺栓强度：`ASTM F1554 / ASTM A325`；
     * 柱体结构力学：`EN 40-3`；
  2. 依据 [05_three_tier_cta_conversion_funnel.md](./references/05_three_tier_cta_conversion_funnel.md) 落地三级 CTA：
     * **Top-Funnel (轻量探索)**：下载 12m 规格书与安装手册 PDF；
     * **Mid-Funnel (方案测算)**：嵌入吊车租赁 vs 采购 ROI 计算器卡片；
     * **Bottom-Funnel (商务决策)**：嵌入法兰图纸 24h 免费核验与工厂私密报价入口；
  3. 文末固定输出 3–4 组基于买家 PAA 痛点的 FAQ，并生成符合 Schema.org 的 `FAQPage` JSON-LD 结构化数据。

### Step 6: 7 语种矩阵工程与瑞士工商业卡片全景配图
* **目标**：深度集成 `geoflow-article-illustration` 视觉引擎，覆盖全站 7 种目标语言（`en`, `es`, `fr`, `pt`, `vi`, `th`, `id`）及备用母语（`zh`）。以 Playwright 自动化渲染具备极高机械制造严谨感的高清卡片阵列，全量消除 AI 洗稿感，并将 5 张技术图表及专属语种工程图注自动回写挂载至 Markdown 正文。
* **执行规范**（详见 [07_b2b_article_visuals_and_card_spec.md](./references/07_b2b_article_visuals_and_card_spec.md)）：
  1. **全套交付图谱清单**（保存在 `geo-drafts/articles/images/<slug>/`）：
     * `cover-flow-hero-16x9.png`（1920×1080 Google Flow MCP 真实感工程封面大图，结合设备白底参考图与文章重点工况生成电影级摄影底图并融合多语言排版，写入 Frontmatter `coverImage`）；
     * `01-feature-hero-cover-16x9.png`（1920×1080 瑞士排版全景工程卡，集成品牌、300kg/12m/85kg/24V KPI 矩阵及产品透明立姿抠图）；
     * `02-two-module-architecture-16x9.png`（1920×1080 机械架构图，45kg 主机 + 40kg 电控箱分体解构）；
     * `03-flange-pcd-compatibility-16x9.png`（1920×1080 通用底板法兰适配图，P.C.D. 180-260mm 径向腰孔力学分析）；
     * `04-sop-field-workflow-16x9.png`（1920×1080 标准三阶段双人地面作业流程 SOP 与高压安全距离引证）；
     * `05-crane-vs-lifter-comparison-16x9.png`（1920×1080 16 吨汽车起重机 vs 便携式立杆机全景对比决策矩阵）；
     * `social-3x4-01-cover.png`（1080×1440 移动端/LinkedIn/小红书出海高密度轮播卡）；
     * `square-1x1-thumb.png`（1080×1080 独立站列表与微信方封面缩略图）。
  2. **自动化驱动命令**：
     * **矩阵流水线一键生成**（推荐，全语种草稿 + Flow 封面图 + 7 卡位图 + 自动入库）：
       ```bash
       npm run matrix:generate -- --topic portable-light-pole-lifter-explainer
       ```
     * **生成 Google Flow 封面大图并回写**：
       ```bash
       npm run visuals:cover -- --article geo-drafts/articles/portable-light-pole-lifter-explainer-en.md --insert-markdown
       npm run visuals:cover:all
       ```
     * **单篇独立渲染与回写 7 卡位图**：
       ```bash
       npm run visuals:generate -- --article geo-drafts/articles/portable-light-pole-lifter-explainer-en.md --insert-markdown
       ```
  3. **门禁、图注与前端同步规范**：
     * 每张图片必须携带专属语言的 `*Figure N: ...*` 斜体图注，注明具体物理参数；
     * 正文 5 张核心图表必须按 Section 顺序精准插入对应小节下方，末尾自动断言 `finalCheck >= 5`；
     * 配图路径统一指向 `/images/<slug>/...`，GEOFlow Docker 容器内挂载直通服务，实现本地后台直通展示；
     * **Astro 前端公共资源双写同步**：配图脚本导出时须同步将纯图片资源（`.png` 等）复制到 `maquin-astro-theme/public/images/<slug>/`，**严禁将 `deck.html` 同步至 public**，杜绝污染全站静态构建断言。

### Step 7: GEOFlow 后台持久化入库与集中人工审核闭环
* **目标**：彻底打通生成管线与生产业务数据库，实现单主题多语言草稿一键入库，强制待审状态，并在 Astro 前端通过官方标准 `MediaFigure` 组件实现头图与 4 处技术图表的无缝挂载与灯箱交互。
* **执行步骤**：
  1. **一键同步至 GEOFlow 本地数据库**：
     * 运行同步脚本，自动解析 Markdown 元数据、正文内容、配图路径与分类：
       ```bash
       npm run geoflow:sync -- --all
       # 或指定单篇 / 单主题同步
       npm run geoflow:sync -- --topic portable-light-pole-lifter-explainer
       ```
  2. **状态硬锁定门禁**：
     * 脚本调用 GEOFlow REST API（`POST/PATCH /api/v1/articles`）持久化写入；
     * 所有文章入库时强制标记为 `status = 'draft'` 且 `review_status = 'pending'`，严禁跳过审核直发生产；
  3. **管理员集中审核工作台**：
     * 访问管理后台：`http://127.0.0.1:18082/geo_admin/articles`；
     * 审核人核验全语种文章的排版格式、图片加载（HTTP 200）、多语言术语准确性及事实台账指标（300kg, 12m, 85kg, 24V, P.C.D. 180-260mm 等）；
  4. **Astro 前端动态模板挂载与全屏灯箱**：
     * Astro 动态文章页 `src/pages/guides/[slug].astro` 自动根据 Slug 定位 public 资源，通过 `MediaFigure` 挂载篇首 16:9 全景头图（`01-feature-hero-cover-16x9.png`）及 4 处小节工程卡片（05 对比矩阵、02 双模组架构、03 法兰适配、04 SOP 流程），支持点击 `↗` 调出 `MediaLightbox` 全屏灯箱；
  5. **Astro 静态发布不可变冻结与回归门禁**：
     * 审核通过后，导出数据执行 `npm run content:prepare` 自动提取 `evidenceRefs` 并生成 SHA-256 签名；
     * 执行 `npm run content:import -- --apply` 写入生产数据源；
     * 运行 `npm test`（30+ 项决策测试、不可变快照哈希校验与 636 项退役检查）全绿后，构建部署生产静态站点。
